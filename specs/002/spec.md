## Overview

外壳 = 一个系统 webview 窗口（Wails v2，WKWebView）套住**既有引擎**：外壳以**锁定态**启动引擎的 `127.0.0.1` 播放服务，窗口加载**登录页**，提交账户口令后解锁私钥并自动重定向到引擎原有的目录树索引页 / 播放页。外壳**不重复实现**封存、启封、目录树与播放 UI，只提供「窗口 + 启动 + 登录 + 禁用 webview 缓存 + 打包」。

首版仅 **macOS arm64**、不签名不公证，经 GitHub Release 分发（zip 内含 `.app` 与 CLI）。

## 依据（已实证，非假设）

`spike`：Wails v2.16.0 在本机 macOS 27.0.1/arm64 上 `wails build -s` 产出 9.1 MB `.app`；直接运行后 WKWebView 由引导页实际导航到 Go 进程的 `127.0.0.1` 随机端口页面并执行其脚本（服务端 marker 的 UA 含 `wails.io`）。构建**不需要 Node/npm**。

## Scope

**包含**：单窗口外壳；loopback 登录页与会话（锁定态启动 → 口令解锁 → 索引页）；**登录页的账户选择**（列出本机可用账户 → 选中账户 → 用该账户的口令解锁）；**登录页的账户管理**（创建 / 恢复 / 删除，仅锁定态可进；见 US9）；**图形化封存**（把视频文件或目录拖进窗口 → 封存到输出目录 → 面板实时进度；见 US10）；复用引擎播放服务与目录树 UI；**引擎内置的库根目录选择页**（浏览子目录 → 设为库根 → 重扫；由外壳持久化）；索引页显示当前库根；空闲锁定回到登录页；退出即关端口并清密钥；禁用 webview 磁盘缓存；`make dist` / `make release`（macOS arm64）；版本号经 ldflags 注入。

**不含**：Windows/Linux 外壳（cgo 外壳无法从 macOS 交叉编译，见 ADR 0001）；签名与公证；**导入任意钱包私钥/助记词的入口**（宪法红线，AC9.5）；外壳内的 mpv 通道；自动更新；登录页账户列表的运行中热加载（登录页仍在启动时发现一次，AC8.1；账户管理页每次渲染重新发现，AC9.1）；封存进度面板之外的封存参数（不提供容器转码、不提供覆盖已存在密档、不提供并发多文件，见 AC10.5）。

## User Stories & Acceptance Scenarios

> 以下 Given/When/Then 是测试用例的唯一来源（L1/L2/L3 均从此派生）。

### US1 启动与登录

- **AC1.1** Given 已安装 `safemedia.app` 且账户文件存在，When 双击启动，Then 打开一个系统 webview 窗口并显示登录页；**全程不出现终端窗口**。
- **AC1.2** Given 登录页，When 输入正确账户口令并提交，Then 解锁并进入引擎原有的索引页 / 播放界面，无需再操作终端。
- **AC1.3** Given 登录页，When 输入错误口令，Then 页面提示口令错误，不进行任何解密，可重试；错误信息不泄露 keystore 内容。
- **AC1.4** Given 账户文件不存在，When 启动外壳，Then 登录页提示需先在命令行创建账户并给出命令，**不自动创建**（红线：只新建、不导入）。
- **AC1.5** Given 外壳已启动，When 检查监听地址，Then 播放服务仅监听 `127.0.0.1` 且端口随机；不得监听 `0.0.0.0`。
- **AC1.6** Given 未登录（锁定态），When 直接请求媒体 URL，Then 被拒绝且不 panic。

### US2 浏览与播放（复用引擎 UI）

- **AC2.1** Given 登录成功，When 进入索引页，Then 显示与 CLI 相同的递归目录树索引页（库根来自上次选择 / `desktop.json` / 默认库）并**显示当前库根路径**，点选条目进入播放。
- **AC2.2** Given 播放页，When 拖动进度条，Then 行为与 CLI/浏览器路径一致（分块独立解密，seek 首字节 < 1s）。
- **AC2.3** Given 播放页左侧常驻目录树，When 点击其它条目，Then 切换片源，与 CLI 目录模式行为一致（**同一份引擎 UI，外壳不另写一套**）。
- **AC2.4** Given 密档被篡改，When 播放或 seek 到被篡改分块，Then 明确报告完整性校验失败，外壳进程不崩溃。
- **AC2.5** Given 白名单内但 WKWebView 无法解码的编码，When 播放，Then 页面给出无法播放的提示（不静默黑屏）。

### US3 锁定与退出

- **AC3.1** Given 播放服务空闲超过 30 分钟（无任何流请求），When 计时到达，Then 服务停止并锁定，窗口回到登录页。
- **AC3.2** Given 已锁定，When 检查窗口，Then 显示登录页且需重新口令才能进入；对媒体 URL 的请求沿锁定态守卫被拒。
- **AC3.3** Given 关闭窗口，When 外壳进程退出，Then `127.0.0.1` 端口关闭、内存中密钥材料清零。
- **AC3.4** Given 外壳已退出，When 检查磁盘，Then 不存在 safemedia 产生的明文视频数据。

### US4 明文不落盘（红线不因外壳放宽）

- **AC4.1** Given 已通过外壳完整播放一个密档，When 检查 webview 缓存目录（`~/Library/Caches/<bundle-id>/`、`~/Library/WebKit/<bundle-id>/`），Then 不存在明文视频数据（外壳必须禁用 webview 磁盘缓存）。
- **AC4.2** Given 播放响应，When 检查响应头，Then 含 `Cache-Control: no-store`。

### US5 构建与分发

- **AC5.1** Given 干净仓库且本机具备 Go 与 Wails CLI，When 执行 `make dist`，Then 在 `dist/` 产出 `safemedia.app`（arm64）、同名 CLI 二进制与一个含版本号的 zip；**构建过程不需要 npm/Node**。
- **AC5.2** Given 构建出的 `.app`，When 在本机双击，Then 能启动（arm64 上的 ad-hoc 签名由 Go 工具链自动满足）。
- **AC5.3** Given 版本注入，When 执行 `safemedia --version`，Then 显示由 `-ldflags -X` 注入的版本（未注入时为 `dev`）。
- **AC5.4** Given `gh` 已登录且已打 tag，When 执行 `make release`，Then 创建 GitHub Release 并把 zip 作为资产上传。
- **AC5.5** Given 发行包，When 解压，Then 其中的 CLI 与 `.app` 来自同一版本、同一提交。

### US6 引擎与 CLI 回归（不退化）

- **AC6.1** Given 引入登录页与外壳的改动，When 运行 `make test`（L1+L2），Then 全绿。
- **AC6.2** Given CLI 既有的 `account` / `seal` / `play` 命令，When 在本改动后运行，Then 用户可见行为与退出码**不变**（`internal/play` 从「先解锁再起服务」重构为「起锁定态服务后可解锁」，但 CLI 流程与输出不变）。
- **AC6.3** Given `make test-l3`，When 执行，Then `tests/e2e/REPORT.md` 仍全 PASS。

### US7 在页面上更改库根（目录选择器）

> 用户 2026-10-15 指示新增：「应该能够在页面上指定扫描目录，像文件浏览器一样，选择完目录后再按子目录结构展示下面的 svid 文件」。

- **AC7.1** Given 已解锁，When 在索引页点「选择密档库」，Then 进入目录选择页：显示当前库根、可编辑的路径输入框、面包屑、上级链接与子目录列表（含每个子目录直接包含的密档数）。
- **AC7.2** Given 目录选择页，When 点某个子目录或面包屑，Then 下钻/回跳该目录，页面与路径输入框同步更新；隐藏项与符号链接不列出（与 `ScanLibrary` 一致）。
- **AC7.3** Given 目录选择页，When 点「使用此目录作为库根」，Then 库根切换为该目录并**立即重扫**（递归 `.svid`），跳回索引页并按新的子目录结构展示。
- **AC7.4** Given 刚切换过库根，When 重新启动外壳，Then 仍使用上次选择的目录（外壳把选择持久化到 `~/.safemedia/desktop.json` 的 `library`，且不覆盖同文件里的 `account`）。
- **AC7.5** Given 提交的路径不存在 / 不是目录 / 不可读，When 提交，Then 页面显示中文错误、**原库根与目录树保持不变**、不 panic。
- **AC7.6** Given 锁定态，When 直接请求 `/library` 或其子路径，Then 不返回目录选择页（回登录页）——锁定态不允许枚举本机目录。
- **AC7.7** Given 外壳以**单个密档**为目标启动（终端带参数），When 打开窗口，Then 以其**所在目录**为库根（外壳始终以库模式运行，`AC2.1` 相应调整）；CLI 的单档模式不变。
- **AC7.8** Given CLI 浏览器模式（`safemedia play <dir>`），When 打开索引页，Then 目录选择器与桌面外壳一致可用（同一份引擎页面），但选择**不持久化**（CLI 无配置文件回调）。
- **AC7.9** Given 任一引擎页面（索引 / 播放 / 选择 / 登录），Then 外观呈现为桌面应用而非网页：可点元素一律是按钮（`<button>` 或 `<a class="btn">`）或整行可点的列表行，**不出现下划线 / 链接色的文字链接**，按钮具备 hover / 按下 / 键盘焦点三态，窗口顶部工具栏与正文列左对齐（用户 2026-10-15 反馈：「模仿桌面应用的，放个超链接就露馅了，一眼就看出来是网页」）。由 `internal/play/page_style_test.go` 守护（不得出现无 class 的裸 `<a>` 与 `text-decoration:underline`）。

### US8 登录页选择账户（多账户）

> 用户 2026-10-15 指示新增：「登录页面，需要能够选择账户，如果有多个账户，需要选对了，才能完成登录。」（本规格原先把「多账户切换」列为不含，此处修订 Scope。）

- **AC8.1** Given `~/.safemedia` 下存在一个或多个 keystore 文件（含 `accounts/` 子目录）或 `desktop.json` 指定了账户文件，When 打开登录页，Then 列出全部可用账户，每项显示**文件名**与**地址短形式**（取自 keystore 的公开 `address` 字段，读取不需要口令）；`desktop.json` 指定的账户排在首位并默认选中；非 keystore 的 JSON（如 `desktop.json`）不得出现在列表中。
- **AC8.2** Given 登录页列出了多个账户，When 选中账户 A 并输入 A 的口令，Then 解锁成功：303 → 索引页并下发会话 cookie。
- **AC8.3** Given 登录页列出了多个账户，When 选中账户 B 却输入账户 A 的口令，Then 提示「口令错误或与所选账户不匹配」、**不进行任何解密**、仍停留在登录页且无会话 cookie；重绘后**保持上次选中的账户**。
- **AC8.4** Given 登录页，When 提交一个不在列表中的账户标识（伪造/篡改），Then 引擎在调用解锁回调**之前**拒绝（提示「请选择一个可用账户」），不读任何账户文件、不尝试解密。
- **AC8.5** Given 账户列表为空（账户文件不存在），When 提交口令，Then 提示先执行 `safemedia account create`，不自动创建（沿用 AC1.4）。
- **AC8.6** Given 任一引擎页面，Then 不出现说明性/免责段落（如「明文不落盘」「只新建账户，绝不导入…」「条目不含原始视频名等元数据」），只保留功能性信息（库根、密档数量、文件名/大小、错误原因）；由 `internal/play/page_style_test.go` 守护（用户 2026-10-15 指示：「把所有的废话说明都去掉」）。**唯一例外**：账户创建页按 AC9.5 显示红线提示（生成密钥前必须让用户看到），守护测试对该页单独放行。
- **AC8.7** Given 锁定态，When 请求登录页，Then **不**枚举本机目录或密档（只读 `~/.safemedia` 下 keystore 的公开地址字段）；登录页的账户列表由调用方扫描一次后注入引擎，引擎自身不遍历文件系统（账户管理页每次渲染重新发现，见 AC9.1）。

### US9 账户管理（登录页入口，仅锁定态）

> 用户 2026-10-15 指示新增：「在 app 上也集成一下账户管理功能吧，可以在 app 上创建、导入、删除账户。」——用户未逐条回答澄清题（要求「以结果导向」直接实现），以下四项由实现者按**宪法 III 红线**与既有惯例拟定，可单独否决/修改（改这四条即可，不影响其它结构）：①「导入」只做**恢复**入口（助记词重建 / 恢复文件重置口令），**不提供**导入任意钱包私钥/助记词的入口（宪法红线不变）；②删除 = 必须提交该账户口令 + 移入回收目录（可还原）；③创建时助记词 = 编号网格展示 + 随机 3 词复述抽查，通过才写文件；④入口在登录页，锁定态可用。

- **AC9.1**（列表）Given 打开登录页，Then 有「账户管理」入口；管理页列出发现到的全部账户（名称 + 地址短形式）并标出配置指定的账户；没有任何账户时显示空状态与「创建账户」入口。列表在**每次渲染时重新发现**——新增/删除后无需重启 app。
- **AC9.2**（创建·写入）Given 管理页发起创建，When 填名称 + 口令（二次一致且通过强度校验）→ 展示助记词 → **复述抽查通过**，Then keystore 写入目标路径，列表出现新账户并显示地址。
- **AC9.3**（创建·不写入）Given 复述抽查失败 / 用户放弃 / 两次口令不一致 / 口令不合格，Then **磁盘上不产生任何文件**（沿用 CLI 既有语义 `MnemonicMismatchWritesNothing`）。
- **AC9.4**（创建·目标路径）Given 本机**没有任何**账户，Then 创建写入默认账户 `<数据目录>/keystore.json`（使 CLI `seal` 默认即用它）；Given 已有账户，Then 写入 `<数据目录>/accounts/<名称>.json`。名称校验：非空、≤64 字符、不含路径分隔符或 `..` 或控制字符、不以 `.` 开头、自动补 `.json`、目标不存在（拒绝覆盖）。
- **AC9.5**（红线）Then **创建页与恢复页**是仅有的两个允许显示红线提示的页面（「本账户仅供 go-safemedia 使用，绝不要把持有真实资产的钱包私钥/助记词导入本工具」）：这两页是用户**交出或拿到助记词**的地方，恢复页尤其可能被用来导入别人的钱包助记词；其余页面（登录/索引/播放/选择/账户列表/删除）仍受 AC8.6 约束、不得出现说明性段落。**不提供**任何导入钱包私钥/助记词的入口。CLI 同理：`account create` 与 `account recover` 都先打印红线提示。守护测试 `internal/play/page_style_test.go` 的 `TestRedlineNoticeOnlyWhereSecretsEnter` + `internal/play/accounts_admin_page_test.go`（创建页）+ `tests/integration/account_cli_test.go`（两条命令）。
- **AC9.6**（恢复·助记词）Given 输入有效助记词 + 名称 + 新口令，Then 重建账户并写入；目标已存在时先把旧文件改名为 `<路径>.bak`（与 CLI `account recover` 一致）；助记词无效 → 页面内中文错误、不写任何文件。
- **AC9.7**（恢复·恢复文件）Given 输入恢复文件路径 + 恢复口令 + 新口令，Then 重置登录口令并写入目标（同上，`.bak` 备份）；路径不存在 / 口令错误 → 页面内中文错误、不写任何文件。
- **AC9.8**（删除·授权）Given 删除某账户，When **未提交该账户的正确口令**，Then 拒绝且不删除任何文件；When 提交正确口令，Then 文件**移入** `<数据目录>/trash/<时间戳>-<名称>`（可还原）而不是直接删除，页面告知「已移入回收目录」与「该账户封的密档将永久无法启封，密档文件本身保留」。
- **AC9.9**（删除·路径边界）Then 只允许删除**数据目录内**、且来自发现列表的账户文件；配置指向数据目录外的账户 → 拒绝并提示手动处理。绝不按任意路径删除文件。
- **AC9.10**（锁定态边界）Then 账户管理路由（`/accounts*`）**仅锁定态可访问**：已解锁时访问 → 303 到 `/`（管理不需要启封任何密档，同时避免「正在播放的账户被删除」的状态歧义）。
- **AC9.11**（配置同步）Given 被删账户正是配置 `account` 指向的文件，Then 外壳清除该字段并落盘（下次启动不再指向已删文件）。
- **AC9.12**（助记词卫生）Then 助记词只存在于本次创建的待确认态：页面 `no-store`、**无「复制」按钮**、不写任何明文文件；确认成功 / 放弃 / 锁定 / 关闭服务后从内存清除；不写日志。

### US10 图形化封存（把视频/目录拖进窗口）

> 用户 2026-10-15 指示新增：「在 app 上集成一下 seal 功能，可以往指定的目录中拖拽视频文件，完成 seal，或者把某个目录拖进来，要给出实时进度。」机制由 Wails 原生文件拖放提供（`options.DragAndDrop.EnableFileDrop` → `runtime.OnFileDrop` 回调给出**绝对路径**，不需要浏览器 DOM 拖放、不依赖 crypto.subtle）。以下四项由实现者按既有惯例拟定，可单独否决/修改：①输出目录默认取库根、可在面板中更改（仅本次会话，不落盘）；②已存在的密档**不覆盖**（跳过并说明），与 CLI 的 `--force` 默认关闭一致；③顺序封存（不并发多文件），避免磁盘与进度读数竞争；④封存运行时空闲锁定不触发、显式锁定中止队列（中止即清理半成品）。

- **AC10.1**（文件）Given 已解锁并停留在索引页，When 把一个 mp4/mov/webm 拖入窗口，Then 该文件被封存到**输出目录**（默认库根），条目在面板中从「等待」变为「封存中」再到「完成」，完成后索引页/目录树出现对应密档且可直接播放。
- **AC10.2**（目录）Given 拖入的是一个目录，Then 递归展开其中白名单视频（跳过隐藏项、符号链接、`.svid`），在输出目录中**保留目录内的相对结构**逐个封存；非白名单文件被跳过并计入「跳过」计数。
- **AC10.3**（实时进度）Then 面板对每个条目显示名称、百分比与已写/总字节、状态（等待 / 封存中 / 完成 / 失败 / 跳过）；至少在封存过程中每秒刷新一次，读数随写入**单调递增**（不是结束时一次性出现）。
- **AC10.4**（白名单与错误隔离）Given 拖入的文件不是 mp4/mov/webm 或本身已是 `.svid`，Then 该条目显示失败与中文原因，**其余条目照常封存**；单个条目失败不使整批失败。
- **AC10.5**（不覆盖）Given 目标密档已存在，Then 不覆盖、条目显示「已存在（跳过）」；该判定在写任何字节之前完成（不得先写后删）。
- **AC10.6**（输出目录）Then 面板显示当前输出目录；可经目录选择页改为其它目录（仅本次会话）；输出目录不可写/不存在时，条目以失败与原因呈现，不 panic。
- **AC10.7**（锁定边界）Given 服务处于锁定态（登录页），When 拖入文件，Then **不写任何文件**（不得创建半成品密档）、不显示进度面板，用户得到可见提示（原生提示框或页面内提示）。
- **AC10.8**（明文红线）Then 拖放只传递**路径**（明文不上传、不进 webview）；引擎读取的是用户本机的原文件、写出的只有密档；封存失败/中止时清理未完成的半成品 `.svid`（与 CLI 同语义：其中不含明文）。
- **AC10.9**（锁定与封存的关系）Then 封存运行期间**空闲锁定不触发**（避免写盘中途被锁）；用户显式点「锁定」会**中止**队列：当前文件中止并清理半成品，未开始的条目标记为已取消；中止后仍正常回到登录页。
- **AC10.10**（完成后刷新）Then 队列结束后自动重扫库根，新密档无需重启 app 即可见可播（与 US7 的重扫同机制）。
- **AC10.11**（CLI 不退化）Then `safemedia seal` 的可见输出、跳过计数与退出码保持原样；输入展开逻辑（白名单/递归/输出路径规则）由引擎与 CLI **共用一份实现**，两处呈现（终端逐条打印 / 页面面板）。
- **AC10.12**（外观）Then 封存面板遵守 AC7.9/AC8.6：原生深色外观、可点元素只有按钮与整行可点行、无说明性废话；进度条与百分比是功能性元素（不受「无废话文案」约束）。

## Non-Functional Requirements

- **NFR-1 体积**：`.app`（含引擎）≤ 15 MB（spike 实测空壳 9.1 MB）。
- **NFR-2 构建**：`make dist` 在本机完成，**不依赖 Node/npm**（`wails build -s` 跳过前端构建）。
- **NFR-3 平台**：首版仅 macOS arm64；不签名、不公证；README 说明 Gatekeeper 的 `xattr -d com.apple.quarantine` 处置。
- **NFR-4 安全**：沿用引擎的分块 AEAD 与 keystore 参数（不因外壳放宽）；外壳禁用 webview 磁盘缓存；服务仅绑环回；媒体 URL 带随机 token。
- **NFR-5 明文不落盘**：外壳不新增任何明文落盘点。
- **NFR-6 依赖**：新增依赖仅 Wails v2（及其传递依赖），须回评审门；不得引入 Node 运行时依赖。
- **NFR-7 可测性**：外壳中可在无 GUI 环境验证的部分（登录页 HTTP、锁定守卫、版本注入、产物命名）必须进 L2；真实窗口行为进 L3。
- **NFR-8 目录选择器的安全边界**：切换/浏览库根只在**已解锁**会话内可用（锁定态回登录页）；页面只列**目录名**（不列文件内容、不读密档元数据）；服务仍只绑 `127.0.0.1`。
- **NFR-9 账户管理的安全边界**：账户管理只在**锁定态**可用（AC9.10）；写入路径由引擎侧的**固定策略**决定（数据目录内、名称校验，AC9.4），不接受任意路径；删除必须口令授权（AC9.8）且限定在数据目录内、来自发现列表（AC9.9）；删除改为移入回收目录而非 unlink；助记词不落盘、不进剪贴板按钮、不写日志（AC9.12）；服务仍只绑 `127.0.0.1`。
- **NFR-10 事务性**：任何失败的创建/恢复/删除都**不留下半成品**（不写文件、不改配置、不动原文件）。
