## 1. 这是什么，能解决什么

`go-safemedia` 把视频**封存**成 `.svid` 密档——只有持有你账户私钥的人才能**启封**播放。它离线运行、不联网、不上链、不做 DRM。

它针对两类风险：

| 风险 | 场景 | go-safemedia 的应对 |
|---|---|---|
| **静态文件泄露** | 笔记本/硬盘/U 盘丢了，或被云盘同步走 | 落盘的是密档，没有账户私钥谁也解不开 |
| **本机明文窥探** | 同机其他人翻你的文件夹、或程序扫描磁盘找 `.mp4` | 磁盘上不存在明文视频，解密只在内存与 `127.0.0.1` 环回响应里 |

**它不做什么（明确边界）：**

- **不防翻录/转发（无 DRM）**：视频一旦在屏幕上播放，用手机拍屏即可复制。go-safemedia 不试图阻止这件事。播放过程中也不屏蔽系统截屏/录屏。
- **不防已取得本机 root/管理员权限的攻击者**：播放时解密后的数据必然经过你的内存，有足够权限的人可以读内存或抓包本地回环流量。
- **不防键盘记录器、不防你自己把助记词拍照发到网上**——见 [第 9 节](#9-安全须知)。
- **不做播放器**：它只负责解密与把流交给系统浏览器（或 mpv），不提供自己的界面皮肤、字幕库、播放列表管理等。

工作原理：

```
视频明文 ──seal──▶ 随机文件密钥 + 分块 AES-256-GCM ──▶ .svid 密档
                        └ 文件密钥用你的账户公钥封装（只有私钥能解）

.svid 密档 ──play──▶ 输入登录口令解锁账户 ──▶ 内存分块解密 ──▶ 127.0.0.1 环回流 ──▶ 浏览器 <video> / mpv
```

## 2. 安装

### 从源码构建（推荐）

需要 **Go 1.26 或更高版本**（以 `go.mod` 为准）。

```sh
git clone https://github.com/cc14514/go-safemedia.git
cd go-safemedia
make build            # 产物：bin/safemedia
```

把产物放到 PATH 里（任选其一）：

```sh
sudo install -m 0755 bin/safemedia /usr/local/bin/safemedia
# 或
mkdir -p ~/bin && cp bin/safemedia ~/bin/ && echo 'export PATH="$HOME/bin:$PATH"' >> ~/.zshrc
```

验证：

```sh
safemedia version     # → go-safemedia 0.2.0-dev（发布包会显示注入的版本号，如 v0.2.0）
safemedia --help
```

### 桌面版（macOS，首版）

不想开终端就用桌面版：一个原生窗口套系统 webview，内部是**同一个环回引擎**，目录树与播放页与浏览器模式完全一致。首版仅支持 **macOS / Apple Silicon**，**不做签名与公证**。

**从 Release 安装**：

```sh
# 1) 下载 safemedia_<版本>_darwin-arm64.zip 并解压（内含 safemedia.app 与 CLI）
# 2) 首次被 Gatekeeper 拦住时，执行一次（未签名分发的正常现象）：
xattr -dr com.apple.quarantine /Applications/safemedia.app
# 3) 双击 safemedia.app
```

**从源码构建**（需要 `wails` CLI 与 Xcode 命令行工具，**不需要 Node**）：

```sh
go install github.com/wailsapp/wails/v2/cmd/wails@v2.16.0
make desktop          # 产物：desktop/build/bin/safemedia.app
make desktop-run      # 构建并直接运行（调试用）
```

**用法**：启动后先是**登录页**（服务以锁定态起步，不存在任何自动解锁路径），输入账户口令后进入目录索引页，点选即播。空闲 30 分钟自动回到登录页（服务不退出），在登录页输入口令可再次解锁；⌘Q 退出。

**看哪个库**（优先级从高到低）：

1. 配置文件 `~/.safemedia/desktop.json` 的 `library`（**推荐**，双击即生效）：`{ "library": "/Users/you/vaults" }`
2. 默认库 `~/.safemedia/library`（不存在时自动创建）。

> 启动参数（`open -a safemedia.app --args ~/vaults`、拖放到图标上）**在 macOS 上不可靠**：经 LaunchServices 启动时参数不会送达进程（实测 macOS 27 下无效）。只在**从终端直接运行二进制**时可用，例如 `make desktop-run ARGS=~/vaults`。

封存视频、新建账户、恢复账户仍走命令行（`safemedia seal` / `safemedia account create`）——桌面版是播放外壳，不含封存与账户管理入口。

**明文不落盘在桌面版同样成立**：明文只经 `127.0.0.1` 环回、响应头一律 `no-store`，系统 webview 的缓存目录不留任何明文（对照实验见 `tests/e2e/REPORT.md` 的「002 桌面外壳」段）。

### 运行时依赖

| 组件 | 是否必需 | 说明 |
|---|---|---|
| 系统浏览器 | 必需（浏览器模式） | Safari / Chrome / Edge / Firefox 均可，由系统默认浏览器打开播放页 |
| `mpv` | 可选 | 仅当你要看浏览器解不了的视频（典型：HEVC/H.265）时用 `--player mpv` |
| Go 工具链 | 仅构建需要 | 运行 `safemedia` 本身不需要 Go |

平台支持：macOS、Linux、Windows 都能构建与运行（拉起浏览器分别用 `open` / `xdg-open` / `rundll32`）。本仓库的自动化测试在 macOS 上验证。

## 3. 五分钟上手

```sh
# 1) 新建账户：生成助记词 + 设置登录口令
safemedia account create
#    按屏幕提示：抄写助记词 → 复述抽查 → 账户写入 ~/.safemedia/keystore.json

# 2) 封存一个视频（会把你的账户公钥写进密档）
safemedia seal ~/Movies/clip.mp4 -o ~/Vaults/clip.mp4.svid

# 3) 启封播放
safemedia play ~/Vaults/clip.mp4.svid
```

第 3 步会打印一个 `http://127.0.0.1:端口/` 地址并自动打开浏览器，在页面里播放、拖进度条都正常。看完按 `Ctrl-C`（或在页面点「立即锁定并清理密钥」）结束会话，内存中的密钥立刻清零。

> 忘了第 2 步的 `-o`？不给 `-o` 时密档默认输出到**源文件同目录**，名字是 `原文件名.svid`。

## 4. 核心概念与术语

| 术语 | 含义 |
|---|---|
| **账户** | 一对 secp256k1 密钥。私钥加密保存在 keystore 文件里，**地址**（`0x…`）是它的公开标识 |
| **助记词** | 12 或 24 个单词。**重建账户的唯一凭证**，等价于私钥，务必离线抄写 |
| **登录口令** | 解锁 keystore 文件的口令。丢失可用助记词或恢复文件找回（见 [第 7 节](#7-备份与恢复丢了什么用什么救)） |
| **恢复口令** | 保护「恢复文件」的独立口令，与登录口令不同 |
| **恢复文件** | `recovery.json`，用恢复口令保护的账户副本，用于**忘记登录口令**时重置 |
| **密档（Vault）** | `.svid` 文件，封存后的加密产物 |
| **封存（Seal）** | 把视频导入成密档 |
| **启封（Unseal）** | 播放时把密档解密 |
| **分块** | 密档按 4 MiB 独立加密，所以能精确跳转到任意位置（拖进度条） |
| **文件密钥** | 每个密档一把随机密钥，用你的账户公钥封装，只有你的私钥能解出 |
| **密档库 / 目录树** | 一个目录（含各级子目录）中的密档合集；`play <目录>` 时按目录树展示，播放页左侧常驻、可随时切换片源 |
| **引擎（Engine）** | 核心加解密与播放服务（`internal/…`）：封存、启封、环回播放、目录树、空闲锁定 |
| **桌面外壳（Desktop Shell）** | 承载引擎的桌面窗口（Wails；`desktop/`）：只把系统 webview 指向引擎的环回地址，不含自己的界面逻辑 |
| **登录页（Login Page）** | 桌面外壳的入口页：服务以锁定态起步，输入口令后解锁进入目录树；空闲锁定后回到此页 |

> 本工具用「封存/启封」而不是「加密/解密」，用「密档」而不是「加密文件」——**不存在**「转换」「转码」这些动作，视频流原样保留。

## 5. 命令参考

### 5.0 全局

```
safemedia [command] [flags]

全局 flag:
  --account string   账户 keystore 路径（默认 ~/.safemedia/keystore.json）
  -h, --help
```

`--account` 作用于所有子命令。用它可以在同一台机器上维护多个互不相通的账户（例如工作用与私人用）：

```sh
safemedia --account ~/.safemedia/work.json account create
```

命令总览：`account`（账户管理）、`seal`（封存）、`play`（启封播放）、`version`（版本）。

### 5.1 `account create` — 新建账户

```sh
safemedia account create [--words 12|24]
```

| flag | 默认 | 说明 |
|---|---|---|
| `--words` | `12` | 助记词词数：`12` 或 `24` |

交互流程：

1. 打印红线提示（**只新建账户，绝不要导入持有真实资产的钱包密钥**）。
2. 若账户文件已存在 → 直接报错退出，**不会覆盖**（要重建请先备份并手动删除）。
3. 设置登录口令，要求**输入两次确认**。
4. 显示助记词（编号网格），要求**纸笔抄写**。
5. **复述抽查**：随机抽 3 个词，要求你按序号回填。**答错则不写入任何文件**，整个流程作废。
6. 写入 keystore（权限 `0600`），打印地址与路径。

口令规则（登录口令与恢复口令共用）：

- 至少 **10 个字符**，否则拒绝并要求重输；
- 含常见弱口令片段（`password`、`123456`、`qwerty`、`admin` 等）→ 拒绝；
- 熵偏低时只**警告**不阻断，建议使用一句好记的长句子（例如 `蓝色鲸鱼在周二吃了三碗面`）。

输出示例：

```
✓ 账户已创建
  地址:   0x9858EfFD232B4033E47d90003D41EC34EcaEda94
  账户:   /Users/you/.safemedia/keystore.json
  助记词是唯一可重建账户的东西，请离线抄写保存，切勿截图或联网存储。
```

### 5.2 `account export-recovery` — 导出恢复文件

```sh
safemedia account export-recovery
```

先验证当前登录口令，再让你设置**恢复口令**，然后写出恢复文件：

- 默认路径：与 keystore **同目录**的 `recovery.json`（即默认 `~/.safemedia/recovery.json`）；
- 已存在则不覆盖，需先备份并删除；
- **请把恢复文件与助记词分开存放**：两者同时丢失/同时被窃，保护就失效了。

### 5.3 `account recover` — 恢复账户

```sh
safemedia account recover --from-mnemonic
safemedia account recover --from-recovery <path>
```

两个来源**必须二选一**：

| 用法 | 适用场景 | 需要什么 |
|---|---|---|
| `--from-mnemonic` | 账户文件丢失或损坏、口令也忘了 | 助记词 |
| `--from-recovery <path>` | **只忘了登录口令** | 恢复文件 + 恢复口令 |

行为：

- 校验来源有效后，要求设置**新的登录口令**；
- 若目标位置已有账户文件，会先重命名为 `keystore.json.bak`，再写入新文件；
- **地址不变**（同一助记词 → 同一私钥 → 同一地址），因此**旧密档无需重新封存**，恢复后直接能播。

```sh
# 丢账户文件、只剩助记词
safemedia account recover --from-mnemonic
#  请输入助记词（空格分隔）: abandon abandon ... about
#  设置新的登录口令: ********
#  ✓ 账户已恢复并写入 ~/.safemedia/keystore.json
```

### 5.4 `seal` — 封存视频

```sh
safemedia seal <视频文件|目录>... [-o <输出>] [--force]
```

输入可以是**视频文件**，也可以是一个**目录**——目录会被**递归遍历**，其中的视频逐个封存。可以一次给多个输入。

| flag | 说明 |
|---|---|
| `-o, --out` | 输出位置。单个视频 → 密档文件路径；目录输入（或多个输入）→ **输出目录**，源目录的相对子路径在其中重建 |
| `--force` | 覆盖已存在的密档（默认遇到已存在则跳过并报错） |

**输出规则**：

| 输入 | 输出 |
|---|---|
| `clip.mp4` | `clip.mp4.svid`（写在源文件旁边） |
| 目录 `Movies/` | 每个 `a.mp4` → `a.mp4.svid`，就地写在它旁边 |
| 目录 `Movies/` + `-o Vaults` | `Movies/a.mp4` → `Vaults/a.mp4.svid`；`Movies/2024/b.mov` → `Vaults/2024/b.mov.svid` |
| 多个文件 + `-o Vaults` | 每个都放到 `Vaults/`（此时 `-o` 一律当输出目录） |

目录遍历时会**自动跳过**：隐藏文件与隐藏目录（`.` 开头）、符号链接、已有的 `.svid`、非白名单文件（按文件头部嗅探），以及输出目录自身。跳过数量在开头报告；输出目录不存在会自动创建。

要点：

- **不转码**：密档 = 原文件 + 极小的认证开销（156 B 头部 + 每 4 MiB 块 28 B）。实测 256 KiB 的文件约 **+0.07%**，文件越大比例越趋近于 0。
- **白名单容器**：`mp4`（ISO BMFF，`ftyp`）、`mov`（`ftyp` 且 brand 为 `qt  `）、`webm`（EBML DocType `webm`）。**`mkv`/`avi`/`flv` 会被拒绝**——浏览器无法原生播放它们。
- **显式传入的文件**若不在白名单内，会**直接报错**（退出码 1）；目录遍历时则静默跳过并计数。
- 一个视频都没找到时直接报错退出（退出码 1），不会「静默成功」。
- 封存需要解锁账户（要读出公钥），因此会先问登录口令。
- 明文只在内存中流过，**磁盘上不会出现明文副本**，也不产生临时文件。
- 终端会显示百分比进度；重定向到文件时自动静默，避免污染脚本输出。
- 中途 `Ctrl-C` 只会留下一个**不完整的 `.svid`（不含明文）**，删除后重跑即可（或加 `--force` 覆盖）。

```sh
# 单个视频
safemedia seal ~/Movies/clip.mp4 -o ~/Vaults/clip.mp4.svid
# ✓ clip.mp4.svid 容器=mp4 明文=255.3 KiB 块数=1  +0.1%

# 目录 → 目录：递归，保持子目录结构
safemedia seal ~/Movies -o ~/Vaults
# 跳过 1 个非视频文件
# 输入登录口令:
# 使用账户 0x… 的公钥封存 3 个文件
# 封存 /Users/me/Movies/a.mp4
#    → /Users/me/Vaults/a.mp4.svid
# ✓ a.mp4.svid 容器=mp4 明文=8.8 KiB 块数=1  +2.0%
# 封存 /Users/me/Movies/2024/iphone.mov
#    → /Users/me/Vaults/2024/iphone.mov.svid
# ✓ iphone.mov.svid 容器=mov 明文=8.8 KiB 块数=1  +2.0%
# ✓ 共 3 个文件封存完成
```

### 5.5 `play` — 启封播放

```sh
safemedia play <密档文件>
safemedia play <目录>
safemedia play <密档文件> --player mpv
```

| flag | 默认 | 说明 |
|---|---|---|
| `--player` | `browser` | `browser`（浏览器播放页）或 `mpv`（交给本机 mpv） |
| `--idle` | `30m` | 空闲超过该时长自动锁定并清零密钥（如 `--idle 10m`） |
| `--no-browser` | `false` | 不自动打开浏览器，只打印地址 |

**单文件模式**：

```
▶ 播放服务已就绪（仅本机）：http://127.0.0.1:52341/
  容器=mp4 明文=255.3 KiB
  播放中按 Ctrl-C 结束；密钥会立即从内存清零。
```

播放页包含：密档文件名标题、`<video>` 播放器、**「立即锁定并清理密钥」按钮**；如果这个视频的编码浏览器解不了，页面会浮出提示**改用 `--player mpv`**。

**目录模式**：**递归**扫描目录及其子目录下的 `.svid`，输出一个按**目录树**（可折叠）分组的索引页（只显示密档文件名与大小，点进条目后单条播放）。

```
▶ 密档库索引已就绪（仅本机）：http://127.0.0.1:52342/
  共 3 个密档（递归含子目录，按目录树展示）
```

索引页里的目录按层级折叠展开，例如：

```
密档库
└─ 2024/
   ├─ ep1.mp4.svid
   └─ ep2.mp4.svid
   top.mp4.svid
```

**播放页左侧常驻目录树**：从索引页点进任意条目后，页面左侧一直显示整个库的目录树，当前播放的条目高亮、滚动到可见位置，**点其它条目即可直接切换片源**（不必退回列表）。浏览器全屏播放时只渲染视频元素，目录树自然退出、不遮挡画面；窗口较窄（≤820px）时目录树自动移到播放器上方。

目录为空不会报错，索引页会给出「先运行 safemedia seal」的提示。扫描会跳过隐藏项（`.` 开头）与符号链接（避免把库外的密档列进来）。

**mpv 模式**：把环回流地址交给本机 mpv。启动前会先探测 mpv 是否安装，**缺失则直接报错退出（退出码 3）**，不会先启动服务。mpv 退出后自动清零密钥并关闭服务。目录模式不支持 mpv（会明确提示）。

**锁定语义**（三种途径，效果相同）：空闲超时、页面「立即锁定」按钮、`Ctrl-C`。锁定后**内存中的文件密钥与账户私钥立即清零**，服务关闭，之后任何媒体请求都会被拒绝。

### 5.6 `version`

```sh
safemedia version     # go-safemedia v0.1.0-dev
```

## 6. 典型工作流

### 6.1 备份一段私人视频

```sh
safemedia account create                       # 一次性：建账户并抄写助记词
safemedia seal ~/Movies/private.mov -o ~/Vaults/private.svid
rm ~/Movies/private.mov                        # 确认密档能播之后再删明文
safemedia play ~/Vaults/private.svid
```

**建议顺序**：先封存 → 先播放验证一遍 → 再删除明文。密档坏了而明文已删，就找不回来了。

### 6.2 批量封存整个相册

```sh
safemedia seal ~/Pictures/iPhone -o ~/Vaults/iPhone
safemedia play ~/Vaults/iPhone                 # 目录模式：按目录树浏览，浏览器点选播放
```

相册里的**子目录结构会原样保留**（例如 iPhone 的 `2024/` 会在输出目录下重建），但隐藏文件、符号链接与非视频文件会被跳过。

想覆盖上一轮的结果：加 `--force`。

### 6.3 建一个自己的「密档库」

把不同来源的密档集中到一个目录，随时 `safemedia play ~/Vaults/` 浏览。索引页不显示原始文件名、时长、分辨率等元数据——密档文件名本身就是全部可见信息，所以**密档文件名请自己起得有信息量但别泄密**。

**用子目录分门别类是推荐做法**：`play` 会递归遍历，索引页与播放页左侧都按目录树展示，播放中也能直接点其它条目切换片源。

```sh
~/Vaults/
├── 2024/                  # 按年份归档
│   ├── trip.mp4.svid
│   └── party.mov.svid
└── iPhone/                # 按来源归档
    └── 2024/
        └── IMG_0001.mov.svid

safemedia play ~/Vaults/    # 一次浏览全部子目录
```

后续追加只需再 `seal` 进同一个目录（或它的子目录）；下一次 `play` 就会出现在树里。目录树只在启动时扫描一次，**追加后重启一次 `play` 即可看到**。

### 6.4 换电脑 / 搬运到另一台机器

密档是**自包含**的（文件密钥封在密档里），账户是可搬运的（keystore 文件）：

```sh
# 旧机：把账户与密档拷到 U 盘
cp ~/.safemedia/keystore.json /Volumes/U盘/
cp -R ~/Vaults /Volumes/U盘/

# 新机：安装 safemedia 后
mkdir -p ~/.safemedia && cp /Volumes/U盘/keystore.json ~/.safemedia/
cp -R /Volumes/U盘/Vaults ~/Vaults
safemedia play ~/Vaults/xxx.svid
```

没有 USB/网盘也不要紧——**只带助记词**即可在新机重建同一账户：

```sh
safemedia account recover --from-mnemonic      # 输入助记词 + 新登录口令
# 之后把密档拷过来即可播放（公钥未变）
```

异地账户可用 `--account` 指定路径，不必放在默认目录。

### 6.5 iPhone 录的视频（.mov / HEVC）

iPhone 录的是 `.mov`（QuickTime 容器），在白名单内，可直接封存。播放取决于编码：

- **「兼容性最佳」格式（H.264）**：Safari / Chrome / Edge / Firefox 都能播。
- **默认「高效」格式（HEVC/H.265）**：Safari 与较新版 Chrome 能播；**Firefox 通常不能**。播放页检测到播不动会自动提示改用：

  ```sh
  safemedia play ~/Vaults/IMG_1234.mov.svid --player mpv
  ```

（浏览器无法原生播放 `mkv/avi`；`mov→mp4` 的无损转封装排期在二期，当前如需 mp4 请先用别的工具转换**后再**封存。）

### 6.6 能把密档分享给朋友吗？

MVP 阶段**不能**：密档只有「封存时那个账户」的私钥能启封，而私钥不外借。多人共享/授权是二期方向（计划中预留了「多用户授权」的空间）。当前要把视频给别人，只能先启封成明文再发——那就失去了保护意义，请自行评估。

## 7. 备份与恢复：丢了什么用什么救

| 丢失的东西 | 用什么救回来 | 结果 |
|---|---|---|
| **登录口令**忘了 | 恢复文件 + 恢复口令（`account recover --from-recovery <path>`） | 重置登录口令，地址不变，密档照旧可播 |
| **账户文件**（keystore）丢了/坏了 | 助记词（`account recover --from-mnemonic`） | 重建同一账户（同地址），密档照旧可播 |
| **登录口令 + 账户文件**都丢了 | 助记词 | 同上（助记词不依赖任何文件） |
| **助记词 + 恢复文件**都丢了，只剩 keystore 但口令忘了 | ❌ 无法找回 | 密档永久打不开 |
| **密档本身**损坏/误删 | ❌ 无法找回 | 只能重新封存原视频（若还有明文） |

**推荐的备份组合**（互相独立、分开存放）：

1. 助记词：纸笔抄写，放保险箱/抽屉。**不要**截图、不要存网盘、不要发微信给自己。
2. keystore + 恢复文件：拷到 U 盘或离线硬盘，与助记词**分开**放。
3. 若干个 `.svid`：随手扔云盘都行——**密档本身泄露不等于内容泄露**（前提是私钥没泄露）。

> 一句话：**助记词是根**。密档能丢能重封，助记词丢了（且恢复文件也丢了）就彻底完了。

|---|---|---|---|---|
| `mp4` | H.264 + AAC | ✅ 全部主流浏览器 | ✅ | 最稳的组合 |
| `mp4` | HEVC/H.265 | Safari ✅ / 新 Chrome ✅ / Firefox ❌ | ✅ | 播不动时用 `--player mpv` |

## 9. 安全须知

### 威胁模型

防的就是 [第 1 节](#1-这是什么能解决什么) 表格里的 a（静态文件泄露）与 b（本机明文窥探）。**不防**：防翻录 DRM、已获 root 的攻击者、键盘记录、你自己把助记词泄露出去。

### 明文不落盘的机制

1. 封存：读一块 → 加密一块 → 写一块，明文只在内存缓冲里停留瞬间；
2. 播放：解密按 4 MiB 块即时进行，**只**通过 `127.0.0.1` 环回端口送出给本机浏览器/mpv；
3. 全程**不创建临时明文文件**，进程也不以任何方式打开原始明文视频（L3 用例会检查这一点）。

### 会话与锁定

- 播放服务只绑 **`127.0.0.1`**，局域网内其他机器访问不到；
- 默认空闲 **30 分钟**自动锁定（可调 `--idle`）；
- 锁定 / `Ctrl-C` / 关闭命令行窗口 → 文件密钥与账户私钥**从内存清零**，服务关闭；
- 锁定后媒体请求一律被拒（返回错误而不是数据）。

### 口令与助记词卫生

- 登录口令至少 10 字符，推荐**一句长口令**（长度比复杂度更有效）：`我在周二买了三斤香蕉和一把伞`；
- 助记词**只抄写在纸上**，不要拍照、不要存剪贴板、不要发给自己；
- 恢复文件与恢复口令与助记词**分开存放**；
- 不要在多台不可信机器上留 keystore 的副本。

### 红线（必须遵守）

> ⚠ **本账户仅供 go-safemedia 使用。绝不要把持有真实资产的钱包私钥/助记词导入本工具，也不要复用同一助记词。**

原因：go-safemedia 的账户复用以太坊账户格式（secp256k1 + keystore v3 + 助记词）。复用意味着**一处失窃，两处全完**。好消息是「同一助记词在 MetaMask 里会得到同一个地址」，你可以用它来**验证**账户推导是正确的，但**不要**反过来把真钱包的助记词拿来这里用。

`account create` 每次都会打印这条提示；本工具也**没有**任何「导入私钥/导入助记词」的命令——这是刻意的设计。

## 10. 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| `✗ 账户不存在：~/.safemedia/keystore.json（先运行 safemedia account create）` | 还没建账户，或 `--account` 指错了 | `safemedia account create`，或指定正确的 `--account` |
| `✗ 口令错误或 keystore 已损坏` | 口令输错；或 keystore 文件被改动过 | 重试；确实忘了 → 用恢复文件/助记词 `account recover` |
| `✗ 口令至少需要 10 个字符` / 含弱口令片段 | 口令不合格 | 换一句长口令 |
| `✗ 不是密档文件或头部已损坏` | 文件不是 `.svid`，或头部被破坏 | 确认路径；损坏的密档无法修复，只能重新封存 |
| `✗ 该密档不属于当前账户` | 用了别的账户的 keystore（例如换账户后播放旧密档） | 用 `--account` 指向正确账户；或按 [6.4](#64-换电脑--搬运到另一台机器) 恢复正确账户 |
| `✗ 不支持的视频容器：仅支持 mp4、mov、webm` | 源文件是 `mkv`/`avi`/`flv` 等 | 先无损转封装成 mp4，再封存 |
| 播放中报错 / 页面「完整性」提示，进程不崩 | 密档块被篡改（GCM 校验失败） | 从备份恢复密档；本工具**不会**返回错误数据 |
| 浏览器打开是白屏/播不动 | 编码浏览器不支持（典型 HEVC + Firefox） | 用 `--player mpv`；或换 Safari/Chrome |
| `✗ 未检测到 mpv：请先安装 mpv，或改用浏览器模式` | 用了 `--player mpv` 但没装 mpv | 装 mpv（`brew install mpv` / `apt install mpv`），或去掉 `--player mpv` |
| `⚠ 无法自动打开浏览器（…），请手动访问上面的地址` | 系统无默认浏览器/无 `xdg-open` | 复制打印出的 `http://127.0.0.1:…` 手动打开；服务会继续运行 |
| 目录模式显示「没有 .svid 密档」 | 目录及其子目录里确实没有密档 | 先 `seal`，或换目录 |
| 子目录里的密档没出现在目录树里 | 该子目录名以 `.` 开头（隐藏目录），或是符号链接 | 取消隐藏 / 把密档移入普通目录（扫描刻意跳过这两类，避免列出库外文件） |
| `play <目录>` 后新封存的密档没出现 | 目录树在启动时扫描一次 | 关掉再重新 `play`（或对单文件直接 `play`） |
| `✗ xxx.svid 已存在（用 --force 覆盖）` | 目标密档已在 | 加 `--force`，或改 `-o` |
| `✗ 没有找到可封存的文件（支持的容器：mp4 / mov / webm）` | 输入目录里没有白名单视频（或有，但都是隐藏项） | 确认容器；`mkv`/`avi`/`flv` 需先无损转封装成 mp4 |
| `跳过 N 个非视频文件` | 目录里混有非视频文件 | 正常提示，不是错误；如需一并封存请先转封装 |
| `✗ mpv 模式请指定单个密档文件` | 目录 + `--player mpv` | mpv 模式只支持单文件 |
| 封存中断，留下一个 `.svid` | `Ctrl-C` | 直接删除它（其中不含明文），或加 `--force` 重跑 |
| 播放久了自动停了 | 空闲超过 `--idle`（默认 30m） | 重新运行 `play`；需要更久就调大 `--idle` |
| 想看详细播放状态 | — | 用 `--no-browser`，在浏览器开发者工具里看 `<html data-decode="…">` |

## 11. 进阶：格式、退出码、脚本化

### 11.1 `.svid` v1 格式

定长头部 **156 字节**（小端），其后是分块正文（默认块 4 MiB）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | magic `SVID` |
| 4 | 1 | 版本（=1） |
| 5 | 1 | 密码套件 |
| 6 | 1 | 容器提示（mp4/mov/webm，仅用于给浏览器正确的 MIME） |
| 7 | 4 | 块大小 `chunk_size` |
| 11 | 8 | 总块数 `chunk_count` |
| 19 | 8 | 明文总长 `plaintext_size` |
| 27 | 65 | 一次性公钥（临时 secp256k1 公钥，非压缩点） |
| 92 | 32 | 被封装的文件密钥（AES-256-GCM 密文） |
| 124 | 16 | 封装用 GCM tag |
| 140 | 12 | 封装用 nonce |
| 152 | 4 | 保留 |

正文每块：`nonce(12) ‖ 密文(≤4 MiB) ‖ GCM tag(16)`，**每块独立随机 nonce**。块偏移由 `chunk_size` 直接算出（隐式索引），所以跳转是 O(1)。

文件密钥封装流程：临时密钥对 × 账户公钥做 ECDH → HKDF-SHA256 派生 → AES-256-GCM 加密 32 字节文件密钥。**密档里不存账户地址**——不属于你的密档在启封时会直接报「该密档不属于当前账户」。

### 11.2 退出码

| 码 | 含义 | 例子 |
|---|---|---|
| `0` | 成功 | 封存完成、播放正常结束、`version` |
| `1` | 用户/输入错误 | 口令错、不是本账户的密档、容器不在白名单、文件不存在、目录里没有可封存的视频 |
| `2` | 数据错误 | 不是密档/头部损坏、密档被篡改 |
| `3` | 环境错误 | 用了 `--player mpv` 但本机没有 mpv |

（浏览器拉起失败**不算错误**：只打印 URL 继续运行。）

### 11.3 脚本化调用

命令支持从管道读取口令输入（stdin 不是终端时按行读取、不回显）。**但请注意**：

```sh
# 仅用于自动化/测试；交互式使用请直接跑命令，让口令从终端输入
printf '%s\n' "$PASS" | safemedia --account "$KS" seal in.mp4 -o out.svid
```

把口令写进脚本、环境变量或 shell 历史会**削弱**本工具的安全价值——生产使用请老老实实在终端里手动输入。

### 11.4 路径与环境变量

| 路径 | 说明 |
|---|---|
| `~/.safemedia/keystore.json` | 默认账户文件（`--account` 可改） |
| `~/.safemedia/recovery.json` | 默认恢复文件（与账户文件同目录） |
| `~/.safemedia/keystore.json.bak` | `account recover` 时对旧账户的自动备份 |

E2E 测试专用环境变量（日常使用不需要）：`SAFEMEDIA_E2E_SAMPLES`（真实样本目录）、`SAFEMEDIA_E2E_NO_BROWSER=1`（跳过浏览器校验）。

## 13. FAQ

**Q：为什么不干脆做成加密 zip？**
A：Go 标准库不支持加密 zip；而且 zip 对整条流式加密，**无法随机读取中间段**——视频拖进度条需要随机访问（mp4 的 `moov` 索引甚至在文件尾部）。所以用了自定义分块容器。

**Q：能改登录口令吗？**
A：可以，但方式是「恢复」：`account recover --from-recovery <path>` 会带你设置新口令（地址不变）。注意这需要恢复文件与恢复口令。

**Q：加密强度如何？**
A：正文 AES-256-GCM，每块独立随机 nonce；文件密钥用 ECDH(secp256k1) + HKDF-SHA256 封装；keystore 用 scrypt（N ≥ 2^17）+ AES-128-CTR + keccak-256 MAC（标准以太坊 keystore v3 格式，MetaMask/geth 能打开）。

**Q：需要联网吗？上链吗？**
A：完全离线。复用以太坊账户**格式**（密钥算法与文件格式），但**不**连任何区块链、不发送任何遥测。

**Q：密档能放网盘吗？**
A：能，而且推荐——密档泄露不等于内容泄露，前提是私钥/助记词没泄露。

**Q：密档能改名、移动、复制吗？**
A：能。密档自包含，改名/移动/复制都不影响启封；但没有对应的账户就永远打不开。

**Q：加密后体积会变大吗？**
A：几乎不变：156 B 头部 + 每 4 MiB 块 28 B，实测 256 KiB 的文件约 +0.07%（文件越大比例越小）。

**Q：能不能只看密档的一部分？**
A：能。分块加密 + HTTP Range 支持，浏览器拖进度条会精确定位到对应块（毫秒级）。

**Q：为什么 `play` 时还要输口令？不能记住吗？**
A：这是刻意的：每次播放都要求解锁账户，密钥只在会话内存中驻留，空闲或中断即清零。想少输几次就调大 `--idle`。

**Q：能同时开多个播放会话吗？**
A：可以，每个 `play` 进程独立占用一个随机环回端口。
