## 1. 背景与动机

视频文件常在网盘、U 盘、共享目录中流转，文件一旦离开本机，任何拿到它的人都能直接打开播放。需要一个工具把视频**封存**为**密档**：文件被拷走也无法播放，只有持有**账户**并知道登录密码的人**登录**后才能观看。

本仓库原为 go-safe-dir（gocryptfs 文件夹加密方案），该方案已全部作废，仓库将改名为 **go-safemedia**（改名由用户执行）。

## 2. 用户与使用场景

单用户为主（或极少数受信用户），完全离线，无服务器、无账号体系依赖。三个核心场景：

1. **封存**：把本机视频（包括 iPhone 录制的视频）加密成 `.svid` 密档。
2. **播放**：在本机登录账户后，用浏览器（或 mpv）观看密档。
3. **搬运**：把账户文件与密档拷贝到另一台机器，离线播放。

## 3. 威胁模型

**防御目标：**

- a）静态泄露：密档文件被复制、传播，攻击者没有账户。
- b）本机明文窥探：未播放时磁盘上不应存在可读的视频明文；播放中解密流只走 `127.0.0.1`，不落临时明文文件。

**明确不防御：**

- 录屏、翻拍屏幕、再编码转发（DRM 级防翻录不做）。
- 多用户分级授权（MVP 不做，容器格式预留扩展空间）。
- 内存提取、冷启动攻击。

## 4. 功能需求

### FR-1 账户

- FR-1.1 创建账户：生成 secp256k1 密钥对，输出标准 keystore JSON（Web3 Secret Storage v3，scrypt 保护）；创建时强制显示 BIP-39 助记词（默认 12 词，可选 24）并要求抄写确认后才完成。
- FR-1.2 登录密码强度校验，弱密码拒绝。
- FR-1.3 红线提示：绝不导入持有真实资产的钱包私钥/助记词，只新建账户。
- FR-1.4 恢复：助记词可完整重建账户；可另导出恢复文件（独立恢复口令保护），用于忘记密码时重置。
- FR-1.5 账户文件默认位置 `~/.safemedia/`，可用 `--account` 覆盖。

### FR-2 封存

- FR-2.1 容器白名单：`.mp4` / `.mov` / `.webm`；名单外拒绝并提示 `--player mpv` 逃生通道。
- FR-2.2 密档格式 `.svid`：头部（magic + 版本 + ECIES 封装的文件密钥 + 分块索引）+ 正文（4 MiB 分块独立 AES-256-GCM 加密），支持随机访问。
- FR-2.3 头部元数据最小化：不含原始文件名、时长、分辨率。
- FR-2.4 封存不转码、不修改原文件；中断不留明文残留。
- FR-2.5 iPhone 视频（`.mov`，H.264 与 HEVC 两种编码）必须支持。

### FR-3 播放

- FR-3.1 `safemedia play <密档|目录>`：登录 → 本地播放服务 → 自动打开系统浏览器播放。
- FR-3.2 支持随机 seek（拖进度条），首字节延迟 < 1s。
- FR-3.3 目录模式：索引页列出目录内全部密档，点选播放。
- FR-3.4 `--player mpv`：调用本机 mpv 播放解密流（全格式逃生通道，含 HEVC）。
- FR-3.5 浏览器不支持当前编码（如 Firefox + HEVC）时，播放页给出改用 mpv 的提示。

### FR-4 锁定

- FR-4.1 播放进程退出：密钥内存清零、`127.0.0.1` 端口关闭。
- FR-4.2 空闲 30 分钟自动停止播放服务并锁定。

### FR-5 可搬运性

- FR-5.1 账户文件 + 密档拷贝到任何装有 safemedia 的机器，输入登录密码即可离线播放，全程无网络依赖。
- FR-5.2 恢复口令与登录密码独立，泄露其一不影响另一个。

### FR-6 桌面外壳

- FR-6.1 双击 `safemedia.app` 即打开一个系统 webview 窗口，登录后直接播放密档或浏览密档库；全程不出现终端。
- FR-6.2 复用既有播放服务与目录树 UI：外壳不重复实现封存、启封与登录校验。
- FR-6.3 登录在窗口内的登录页完成（仅 `127.0.0.1`）：播放服务以锁定态启动，提交账户口令后解锁并进入索引页；锁定后回到该页。
- FR-6.4 红线不因外壳而放宽：明文不落盘（外壳须禁用 webview 磁盘缓存）、只绑环回、空闲锁定、退出即清密钥。
- FR-6.5 首版仅 macOS arm64、不签名不公证，经 GitHub Release 分发（zip 内含 `.app` 与 CLI）。
- FR-6.6 库根可在界面中更改，不必手工编辑配置文件：索引页提供目录选择页（浏览/下钻子目录 → 设为库根 → 立即重扫并按子目录结构展示 `svid`），外壳记住该选择；锁定态不得进入目录选择页。单密档目标以其**所在目录**为库根。
- FR-6.7 登录页可**选择账户**：列出本机可用账户（`~/.safemedia` 下的 keystore 文件与配置指定的账户文件），每项显示文件名与地址短形式（地址取自 keystore 的公开 `address` 字段，读取不需要口令）；必须选中账户并输入与该账户匹配的口令才能解锁，选错账户时提示不匹配且不进行任何解密；不在列表中的账户标识一律拒绝。账户文件不存在时提示先用命令行创建。
- FR-6.8 登录页只呈现必要信息（当前库根、账户列表、口令输入、解锁动作与失败原因），不呈现说明性/免责段落；红线提示仍保留在 `account create` 的命令输出与文档中（宪法 III「只新建账户」不要求页面展示）。
- FR-6.9 **账户管理**（由登录页进入，仅锁定态可用）：列出本机账户并可**创建**新账户（生成助记词→抄写复述确认→写 keystore）、**恢复**账户（用助记词重建，或用恢复文件重置登录口令）、**删除**账户（须提交该账户口令，文件移入回收目录以便还原，密档文件不受影响）。
- FR-6.10 账户管理**不放宽红线**：不提供导入任意钱包私钥/助记词的入口；创建页是唯一显示红线提示的页面。写入路径由固定策略决定（数据目录内），删除限定在数据目录内且必须是发现到的账户文件，绝不按任意路径写/删。
- FR-6.11 账户管理**不落明文**：助记词只在其待确认状态内存在于内存与页面（`no-store`、无复制按钮、不写文件、不写日志），确认/放弃/锁定/关闭后清除。

## 5. 非目标

- DRM、防录屏、防转发。
- 多用户授权（格式预留，不实现）。
- 转码；mov→mp4 转封装留二期。
- 云端服务、移动端 App。
- Windows 桌面外壳（首版不做：cgo 外壳无法从 macOS 交叉编译，见 `docs/adr/0001`）。
- **导入任意钱包私钥/助记词**（宪法 III 红线：只新建账户；FR-6.10）。
- 封存（seal）的图形界面：外壳只做账户与播放，封存仍走 CLI。

## 6. CLI 草案

```
safemedia account create [--account <path>]
safemedia account recover [--recovery <file>]
safemedia account export-recovery
safemedia seal <video> -o <vault.svid>
safemedia play <vault.svid|dir> [--player mpv] [--account <path>]
```

二进制名 `safemedia`；Go module 路径待仓库改名后确定。

## 7. 关键技术决策（已确认）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 播放形态：浏览器 `<video>` + 本地 HTTP 流；mpv 为逃生通道 | 纯 Go 终端播放不可行；浏览器原生只支持 mp4/webm 容器 |
| D2 | 自定义分块容器 `.svid` | 加密 zip 无法随机读且 Go 标准库不支持；整文件单流加密无法 seek（moov atom 在文件尾） |
| D3 | 以太坊式账户：secp256k1 + keystore v3 + BIP-39，不上链 | 格式成熟、正规钱包工具可校验、助记词便于抄写保存 |
| D4 | 文件密钥用 ECIES 封装到账户公钥 | 一密档一密钥；为未来多用户授权预留空间 |
| D5 | 助记词强制抄写确认 + 独立恢复文件 | 密钥丢失必须可恢复（用户硬需求） |
| D6 | 头部元数据最小化 | 减少静态泄露面 |
