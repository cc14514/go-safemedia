# go-safemedia v0.2.0

把视频**封存**成 `.svid` 密档（每文件一把随机文件密钥、4 MiB 分块 AES-256-GCM），只有持有账户私钥的人能**启封**播放。
纯 Go、完全离线：不联网、不依赖任何服务、无 DRM。明文只在内存与本机 `127.0.0.1` 环回中出现，不落盘。

## 下载

`safemedia_0.2.0_darwin-arm64.zip`，解压后包含：

| 文件 | 说明 |
|---|---|
| `safemedia.app` | 桌面外壳，双击运行（图形界面） |
| `safemedia` | 命令行：建账户 / 封存 / 播放 |
| `说明.txt` | 三步上手说明（与本节内容一致） |

**本版本只提供 macOS aarch64（Apple Silicon）产物。** Intel Mac、Windows、Linux 请自行编译（见下）。

首次打开若提示「无法打开，因为它来自未验证的开发者」——本版本不签名、不公证，终端执行一次即可：

```sh
xattr -dr com.apple.quarantine /Applications/safemedia.app
```

## 能做什么

- **封存**：把 mp4 / mov / webm 封存为 `.svid`（不转码，原画质；4 MiB 分块独立加解密，因此能随机访问、拖进度条不必从头解密）
- **密档库**：把目录当库，递归展示子目录树（保留层级），页面内可随时换扫描目录（选择会被记住）
- **启封播放**：本机环回 HTTP 服务（只绑 `127.0.0.1`）+ 系统 webview 播放；空闲 30 分钟自动锁定并清零内存密钥，也可手动立即锁定
- **图形化封存**：把视频/文件夹拖进窗口，或点「选择视频文件…／选择文件夹…」，逐条显示实时进度；不覆盖已存在的密档
- **账户**：BIP-39 助记词创建账户（以太坊 keystore v3 格式，`m/44'/60'/0'/0/0`，与 MetaMask 同一助记词得到同一地址），支持助记词/恢复文件恢复、口令授权删除

## 从源码构建

```sh
make build            # 命令行 -> bin/safemedia（纯 Go，可交叉编译）
make desktop          # 桌面外壳 -> desktop/build/bin/safemedia.app（仅 macOS，需 Xcode CLT + wails CLI）
make test             # L1 单元 + L2 集成（含 -race）
make test-l3          # L3 端到端，产出 tests/e2e/REPORT.md
```

命令行是**纯 Go、无 cgo**，可交叉编译到其它平台（本版本实测：`GOOS=windows GOARCH=amd64`、`GOOS=linux`、`GOOS=darwin GOARCH=amd64` 均直接产出可执行文件）：

```sh
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -o safemedia.exe ./cmd/safemedia
```

桌面外壳依赖各平台原生 webview（Wails v2），需要在该平台上构建。

## 本版本的验证

- **门禁**：L1 单元 + L2 集成全绿（含 `go test -race`）；L3 端到端 **39 PASS / 0 FAIL**（含真实样本经无头 Chrome 真实解码 mp4/webm/mov 的校验），报告见仓库 `tests/e2e/REPORT.md`
- **明文不落盘**：对照实验（故意可缓存的响应确实落入 webview 缓存，而引擎的 `Cache-Control: no-store` 响应与真实媒体流零残留）验证通过

## 已知限制（刻意不做）

- 只接收 mp4 / mov / webm 容器，不接收 mkv/avi/flv（浏览器与系统 webview 无法原生解码），不提供转码
- 桌面外壳仅 macOS arm64；不签名、不公证
- 不做防翻录 / 防转发（威胁模型只防静态泄露与本机明文窥探，详见 `docs/requirements.md`）
- **只新建账户，绝不导入持有真实资产的钱包私钥/助记词**（避免跨场景密钥复用）
